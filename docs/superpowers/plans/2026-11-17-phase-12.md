## Design decisions

Pure functions and cached immutable reference fit the existing engine boundary. A geodesy dependency adds unnecessary lifecycle cost. Putting math in React or the historical snapshot conflicts with active modular ownership.

Use typed thrown validation errors; strict longitude validation accepts [-180,180], explicit normalization returns [-180,180). Inverse uses bounded fixed-point latitude iteration, normal-projected height and a pole branch. Reject near-center ECEF (radius below half the WGS84 semi-major axis), where geodetic interpretation is ambiguous; no silent defaults. Cache anchor ECEF and trigonometric basis. A fixed worldOrigin maps the anchor to an explicit nonzero local offset; no live rebasing.

## Review Focus

- Missing/null/nonfinite components must throw typed errors, including invalid origins and heading.
- Poles and antimeridian need metric residuals, not longitude equality at poles.
- Nonzero world origin must be applied exactly once and copied before freezing.
- Derived coordinates must never feed physics or imply surveyed height.
- Debug closure must stop conversion sampling, without adding per-frame work.
